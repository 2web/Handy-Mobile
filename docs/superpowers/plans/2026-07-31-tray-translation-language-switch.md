# Tray Translation-Language Switcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a system-tray submenu that switches the translation target language in one click, with a checkmark on the active language.

**Architecture:** Backend-only. A curated shortlist + a pure helper compute the menu entries in `tray.rs`; the submenu is built in `update_tray_menu`; a `translate_lang:{code}` arm in the `lib.rs` tray event handler writes the shared `translation_target_language` setting and rebuilds the menu. Language labels reuse `actions::language_english_name`. The submenu title is a new localized tray string.

**Tech Stack:** Rust (Tauri 2 tray `Submenu`/`CheckMenuItem`), i18n JSON → generated `TrayStrings` (via `src-tauri/build.rs`).

**Spec:** `docs/superpowers/specs/2026-07-31-tray-translation-language-switch-design.md`

## Global Constraints

- Push code ONLY to `origin` (2web/Handy-Mobile). NEVER to `upstream`.
- Windows build: `export CARGO_TARGET_DIR="C:/h"` before any cargo/tauri command. Build a standalone with `bun run tauri build` (a bare `cargo build` produces a DEV-mode exe that needs the Vite dev server). Stop the running app first (`Stop-Process -Name handy -Force`) so the build can stage DLLs.
- Automated `cargo test` cannot execute here (pre-existing `0xc0000139` test-binary launch failure, environmental). Verify pure logic by compile + inspection of the unit tests; verify glue by build + manual tray click.
- Reuse the shared `translation_target_language` setting — switching affects BOTH voice and clipboard translation. No new persistent setting.
- Language item labels are English names via `crate::actions::language_english_name` (keep menu labels and the translation prompt consistent). Do not localize individual language names.
- Curated shortlist only (~14 codes); do NOT render the full ~40-language list.

So the en i18n key must exist before the submenu code compiles. Task 1 adds i18n + the independent helper (which does not reference `strings`), so it compiles alone; Task 2 adds the submenu + handler that depend on the generated field.

```rust
/// Curated common translation targets shown in the tray language submenu.
/// Every code must be one `crate::actions::language_english_name` maps, so the
/// menu label and the translation prompt agree. Exotic languages remain
/// reachable through Settings → Translation.
const TRANSLATION_LANGUAGE_SHORTLIST: &[&str] = &[
    "en", "de", "ru", "es", "fr", "it", "pt", "ja", "ko", "uk", "pl", "tr", "nl", "zh-Hans",
];

/// Ordered entries for the tray language submenu: one per shortlist code, plus
/// the current target appended if it is not already in the shortlist, so the
/// active language is always present and checked. Returns `(code, is_checked)`.
pub(crate) fn language_menu_entries(shortlist: &[&str], current: &str) -> Vec<(String, bool)> {
    let mut entries: Vec<(String, bool)> =
        shortlist.iter().map(|c| (c.to_string(), *c == current)).collect();
    if !shortlist.iter().any(|c| *c == current) {
        entries.push((current.to_string(), true));
    }
    entries
}
```

```rust
let current_lang = settings.translation_target_language.clone();
let language_submenu = {
    let submenu = Submenu::with_id(
        app,
        "translation_language_submenu",
        &strings.translation_language,
        true,
    )
    .expect("failed to create translation language submenu");

    for (code, is_active) in language_menu_entries(TRANSLATION_LANGUAGE_SHORTLIST, &current_lang) {
        let label = crate::actions::language_english_name(&code);
        let item_id = format!("translate_lang:{}", code);
        let item = CheckMenuItem::with_id(app, &item_id, &label, true, is_active, None::<&str>)

    }

    submenu
};
```

- [ ] **Step 3: Add the `translate_lang:` handler (lib.rs)**

In `src-tauri/src/lib.rs`, in the `.on_menu_event(|app, event| match event.id.as_ref() { ... })` block, add an arm immediately after the `model_select:` arm (before the `_ => {}` fallthrough at ~line 307):

```rust
            id if id.starts_with("translate_lang:") => {
                let code = id.strip_prefix("translate_lang:").unwrap().to_string();
                let mut settings = settings::get_settings(app);
                if settings.translation_target_language == code {
                    return;
                }
                settings.translation_target_language = code.clone();
                settings::write_settings(app, settings);
                let _ = app.emit(
                    "settings-changed",
                    serde_json::json!({
                        "setting": "translation_target_language",
                        "value": code
                    }),
                );
                log::info!("Translation language switched to {} via tray.", code);
                tray::update_tray_menu(app, None);
            }
```

(`Emitter` is already imported in lib.rs: `use tauri::{AppHandle, Emitter, Listener, Manager};`. `serde_json` and `log` are available crate dependencies.)
